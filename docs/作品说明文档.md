## 一、作品名称

**NewsFinshied** —— 基于大模型的智能新闻内容采编平台

## 二、主要功能

本系统面向新闻机构，构建覆盖"线索发现 → 选题策划 → 稿件撰写 → 审核发布 → 读者反馈"全流程的智能采编平台。系统分为三大终端：

### 2.1 采编端（Editor）

| 功能模块 | 说明 |
|----------|------|
| **首页仪表盘** | 全站数据概览：选题总数、线索总数、稿件总量、已发布数量、待审核数量 |
| **新闻线索** | 多渠道自动采集（HackerNews / GitHub Trending / 华尔街见闻 / 微博热搜 / V2EX / RSS 订阅源），共 14 个数据源；支持中文关键词搜索；AI 分析新闻价值与传播潜力 |
| **选题策划** | 选题创建、编辑、状态管理（进行中/已完成）；选题与稿件关联 |
| **AI 稿件生成** | 调用 DeepSeek-V3 大模型，支持一键生成标题/摘要/关键词、AI 续写/改写/润色、内容质量自动评分 |
| **稿件管理** | 稿件 CRUD、版本控制、状态流转（草稿 → 待审核 → 审核中 → 已发布）；支持按标题/作者/状态检索 |
| **反馈分析** | 读者端反馈数据聚合统计，浏览量、点赞数、评论数可视化 |
| **个人中心** | 个人信息展示与编辑、头像上传、密码修改、个人统计数据 |
| **系统设置** | 站点名称、Logo、公告等全局配置管理（管理员可编辑，普通用户只读） |

### 2.2 审核端（Review）

| 功能模块 | 说明 |
|----------|------|
| **审核仪表盘** | 待审稿件概览，按优先级/时间排序 |
| **待审队列** | 分页展示待审稿件列表，支持关键词搜索 |
| **AI 预审** | 大模型自动评分，给出通过/需复核/不通过建议 |
| **多级审核** | 支持一级/二级/三级审核，审核意见可回退 |
| **发布管理** | 通过、拒绝、退回修改，发布后自动同步至读者端 |
| **已发布管理** | 已发布稿件列表，支持下线操作 |

### 2.3 读者端（Reader）

| 功能模块 | 说明 |
|----------|------|
| **首页** | 已发布稿件瀑布流展示，分类浏览（科技/财经/体育/娱乐等） |
| **文章详情** | Markdown 渲染正文，AI 自动生成摘要与关键词 |
| **搜索** | 全文搜索，支持按标题、内容、分类检索 |
| **互动** | 评论、点赞功能 |
| **站内消息** | 系统通知与消息中心 |

### 2.4 系统基础功能

| 功能 | 说明 |
|------|------|
| 用户认证 | JWT Token 认证，支持注册/登录/角色鉴权 |
| 角色权限 | 系统管理员、编辑、审稿人三级角色，权限分离 |
| 数据持久化 | MySQL 8.0 关系型数据库，8 张核心表 |
| Docker 部署 | 一键 Docker Compose 编排，兼容 Apple Silicon (M1/M2) |

### 5.2 主要创新点

1. **大模型深度融合**：将 DeepSeek-V3 大模型深度嵌入新闻生产全流程，而非简单的外挂式调用。在**线索分析**（自动评估新闻价值）、**内容生成**（标题/摘要/正文 AI 辅助写作）、**审核预审**（AI 自动评分与建议）三个关键节点均引入大模型能力，形成完整的 AI 辅助新闻工作流。

2. **全流程闭环设计**：系统覆盖从"线索发现"到"读者反馈"的完整新闻生产链路，各环节状态自动流转（线索 → 选题 → 稿件 → 审核 → 发布 → 反馈），实现了新闻编辑室的全链路数字化。

3. **多端分离架构**：创新性地将系统拆分为采编端、审核端、读者端三个独立前端应用，共享同一后端 API。各端面向不同角色的工作流定制 UI，实现职责分离与权限隔离。

4. **智能多源采集引擎**：针对中文网络环境，设计了一套兼容 RSS/API/HTML 三种采集方式的多源新闻线索聚合引擎。针对国内搜索引擎（搜狗/360/百度/头条）均为 JS 动态渲染的特点，采用 Bing 国际版 RSS 接口作为中文关键词搜索的替代方案，解决了静态爬虫无法获取中文搜索结果的难题。

5. **跨平台兼容部署**：从开发阶段即考虑 Apple Silicon (M1/M2) 兼容性，使用纯 Python 驱动 PyMySQL 替代需要 C 编译的 mysqlclient，在 docker-compose.yml 中显式指定 ARM64 平台，确保项目可在 Intel 和 Apple Silicon 两种架构上无缝运行。
