## 一、系统架构

```
┌─────────────────────────────────────────────────┐
│                    前端 (React + Vite)            │
│   /reader     客户端（公开阅读）                   │
│   /editor     采编端（登录 → 写稿/提审）           │
│   /review     审核端（登录 → 审核/发布）           │
└──────────────────────┬──────────────────────────┘
                       │ REST API
┌──────────────────────▼──────────────────────────┐
│                 后端 (FastAPI)                    │
│   /api/auth      认证（登录/注册/Token）          │
│   /api/articles  稿件 CRUD + 提审 + 发布          │
│   /api/reviews   审核记录 + 待审列表              │
│   /api/clues     新闻线索管理                     │
│   /api/collection 素材采集任务                     │
│   /api/topics    选题规划                         │
│   /api/reader    读者端消息/评论                   │
└──────────────────────┬──────────────────────────┘
                       │ SQLAlchemy ORM
┌──────────────────────▼──────────────────────────┐
│                 SQLite 数据库                     │
│   users / articles / reviews / news_clues / ...  │
└─────────────────────────────────────────────────┘
```

## 二、角色与权限

| 角色 | 枚举值 | 职责 | 账号示例 |
|------|--------|------|----------|
| **投稿用户** | `user` | 创建稿件、提交审核、查看自己的稿件 | reporter1 / reporter123 |
| **审核员** | `reviewer` | 审核稿件（通过/拒绝/退修）、查看全部稿件 | reviewer / reviewer123 |

> 审核分为三级：初审（first）→ 复审（second）→ 终审（third），由不同审核员接力完成。

## 三、稿件生命周期

```
 ┌────────┐   提交审核    ┌───────────┐   审核通过   ┌────────┐
 │  草稿  │ ──────────→ │  待审核    │ ──────────→ │  通过   │
 │ draft  │              │ pending   │              │approved│
 └────────┘              │ _review   │              └───┬────┘
      ↑                  └─────┬─────┘                  │
      │                        │                        │ 发布
      │ 退修                    │ 审核中                  │
      │ need_revision          │ reviewing              ▼
      │                        │                  ┌──────────┐
      │                  ┌─────▼─────┐            │  已发布   │
      │                  │  审核中    │            │ published │
      │                  │ reviewing │            └─────┬────┘
      │                  └─────┬─────┘                  │
      │                        │                        │ 过期
      │                        │ 拒绝                   ▼
      │                        ▼                  ┌──────────┐
      │                  ┌──────────┐             │  已归档   │
      └──────────────────│  已拒绝   │             │ archived  │
                         │ rejected │             └──────────┘
                         └──────────┘
```

**7 种状态枚举：**

| 状态 | 枚举值 | 说明 |
|------|--------|------|
| 草稿 | `draft` | 编辑中，尚未提审 |
| 待审核 | `pending_review` | 已提交，等待审核员介入 |
| 审核中 | `reviewing` | 审核员已开始审核 |
| 已通过 | `approved` | 全部审核层级通过，等待发布 |
| 已发布 | `published` | 已对外发布，读者可见 |
| 已拒绝 | `rejected` | 审核不通过 |
| 已归档 | `archived` | 过期/历史内容 |

## 四、完整业务流

### 4.1 采编端流程

```
① 记者创建稿件
   POST /api/articles  →  status = draft
   
② 记者编辑完善内容
   PUT  /api/articles/{id}  →  更新标题/正文/标签等
   
③ 记者提交审核
   POST /api/articles/{id}/submit-review  →  status = pending_review
```

### 4.2 审核端流程

```
④ 审核员查看待审列表
   GET  /api/reviews/pending  →  所有 pending_review 稿件

⑤ 审核员开始审核
   POST /api/reviews  body={article_id, level, result, comment}
   
   审核结果三种：
   ├─ approved        → 该层级审核通过
   ├─ rejected        → 拒绝，稿件状态变为 rejected
   └─ need_revision   → 退修，稿件退回草稿状态
   
   审核层级三级接力：
   ├─ first  (初审)    → reviewer / reviewer3
   ├─ second (复审)    → reviewer2
   └─ third  (终审)    → reviewer3（三级全过 → approved）
   
⑥ 终审全通过 → 返回采编端一键发布
   POST /api/articles/{id}/publish  →  status = published
```

### 4.3 读者端

```
⑦ 已发布稿件在读者端展示
   GET  /api/reader/articles (公开，无需登录)
   
   读者可以：
   ├─ 浏览文章列表和详情
   ├─ 发表评论 (ArticleComment)
   └─ 查看其他读者评论
```

## 五、数据库核心模型

### 5.1 用户表 `users`
```
id | username | email | password_hash | full_name | role | is_active
```

### 5.2 稿件表 `articles`
```
id | title | content | abstract | author | category | tags | 
status | version | creator_id | clue_id | published_at | 
cover_image | images | article_metadata
```

### 5.3 审核记录表 `reviews`
```
id | article_id | reviewer | level(first/second/third) | 
result(approved/rejected/need_revision) | comment | reviewed_at
```
- 每篇稿件可有多条审核记录（对应不同审核层级）
- 审核记录叠加在稿件生命周期中

### 5.4 新闻线索表 `news_clues`
```
id | title | source | source_url | category | keywords | 
news_value_score | propagation_potential | status
```

## 六、API 路由一览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/register` | 读者注册 |
| POST | `/api/auth/login` | 登录获取 Token |
| GET | `/api/auth/me` | 当前用户信息 |
| POST | `/api/articles` | 创建稿件 |
| GET | `/api/articles` | 稿件列表（分页/筛选） |
| GET | `/api/articles/{id}` | 稿件详情（含审核记录） |
| PUT | `/api/articles/{id}` | 更新稿件 |
| DELETE | `/api/articles/{id}` | 删除稿件 |
| POST | `/api/articles/{id}/submit-review` | 提交审核 |
| POST | `/api/articles/{id}/publish` | 发布稿件 |
| POST | `/api/reviews` | 创建审核记录 |
| GET | `/api/reviews` | 审核记录列表 |
| GET | `/api/reviews/pending` | 待审核稿件列表 |
| GET | `/api/articles/{id}/reviews` | 某稿件的审核历史 |
| GET | `/api/clues` | 新闻线索列表 |
