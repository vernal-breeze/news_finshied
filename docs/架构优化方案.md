## 二、后端问题（按严重程度排序）

### 🔴 P0：死代码 — `app/ai_service.py`（493行，完全未被引用）

```
app/ai_service.py          ← 旧版 AIService（493行），N/A 引用
app/services/ai_service.py ← 新版 EnhancedAIService（1632行），已被所有 router 使用
```

**验证：** 用 grep 全项目搜索，没有任何文件 `import` 旧版 `app.ai_service`。新版才是活跃代码。

### 🔴 P0：顶层脚本重复 — `backend/` vs `backend/scripts/`

```
backend/generate_ai_articles.py  ← 3878 字节
backend/scripts/generate_ai_articles.py  ← 3878 字节（完全重复）
backend/seed_data.py             ← 26103 字节
backend/scripts/seed_data.py     ← 26103 字节（完全重复）
```

已迁移到 `scripts/` 目录，但旧文件没删。

### 🟡 P1：Service 实例化散落在各 router 文件顶部（13 处模块级单例）

```python
# routers/articles.py:28
article_service = ArticleService()
topic_service = TopicService()

# routers/clues.py:33
clue_service = ClueService()
ai_service = AIService()

# routers/content.py:21
ai_service = AIService()
article_service = ArticleService()

# ... 一共 13 处分散在各文件
```

**问题：**
- `ArticleService` 在 5 个 router 文件里各自创建了实例（article/stats/public/content/topics）
- 模块级单例缺少生命周期管理
- 应该通过 `routers/__init__.py` 统一导出或改用 FastAPI Dependency

### 🟡 P1：`app/config.py` 未迁入 `app/core/`

`core/` 目录已有 `auth.py`、`exceptions.py`、`logging_config.py`、`security.py`，但 `config.py` 仍留在 `app/` 顶层，与其他已迁移项不一致。

### 🟡 P1：`app/middleware/__init__.py` 混入业务函数

```python
# middleware/__init__.py 不是纯 __init__
async def add_security_headers(request: Request, call_next):
    """添加安全响应头"""   ← 应该独立成文件
```

`__init__.py` 应该只做导出，`add_security_headers` 应独立为 `middleware/security.py`。

### 🟢 P2：7 个向后兼容 stub 文件

```
app/auth.py              ← 2行：from app.core.auth import *
app/clue_collector.py    ← 2行：from app.utils.clue_collector import *
app/exceptions.py        ← 2行：from app.core.exceptions import *
app/logging_config.py    ← 2行：from app.core.logging_config import *
```

这些 stub 是为了向后兼容旧 import 路径。可以保留，但应该标记为 deprecated。

### 🟢 P2：config.py 中 5 个未使用字段

```
DATABASE_POOL_SIZE / DATABASE_MAX_OVERFLOW / DATABASE_POOL_TIMEOUT
DATABASE_POOL_RECYCLE / MAX_ARTICLE_LENGTH
```

这些字段定义了但 `database.py` 没有使用连接池配置，也没有地方校验 `MAX_ARTICLE_LENGTH`。

### 🟢 P2：`app/utils/clue_collector.py`（1578行）和 `app/services/clue_service.py`（1157行）过长

两个文件加一起超过 2700 行，适合进一步拆分。

## 四、优化方案

### 4.1 后端（分两批执行）

#### 第一批：清理死代码（10 分钟，无风险）

| # | 操作 | 文件 |
|---|------|------|
| 1 | 删除旧版 AI 服务 | `app/ai_service.py`（493行） |
| 2 | 删除重复顶层脚本 | `backend/generate_ai_articles.py`、`backend/seed_data.py` |

#### 第二批：架构整理（20 分钟，低风险）

| # | 操作 | 文件 |
|---|------|------|
| 3 | 统一 Service 实例化 | 在 `routers/__init__.py` 创建 DI 依赖，各 router 文件改为 `Depends(get_xxx_service)` |
| 4 | 迁移 config 到 core | `app/config.py` → `app/core/config.py`，`app/config.py` 变 stub |
| 5 | `middleware/__init__.py` 拆分 | `add_security_headers` 独立为 `middleware/security.py` |
| 6 | 清理 config 无用字段 | 删除 `DATABASE_POOL_SIZE` 等 5 个未使用字段 |
| 7 | stub 文件标 deprecated | 在 4 个 stub 顶部加 `warnings.warn(DeprecationWarning)` |

### 4.2 前端（一批执行）

#### 清理死代码（5 分钟，无风险）

| # | 操作 | 文件 |
|---|------|------|
| 1 | 删除顶层重复 pages | `pages/{AIArticle,Analytics,Articles,Clues,Home,Topics,Login,Register}.tsx`（共 8 个文件 ≈ 200KB） |
